# Decisions

One line per decision: `[date] area: chose X over Y — why`. Read before re-opening a settled
question; append when you pick A over B, decline a dependency, or stop because a rule forbade
something. Append-only (`merge=union` in `.gitattributes`).

- [2026-10-30] ci: Dependabot weekly (Sun 22:00 Europe/Stockholm) with a 7-day cooldown and grouped minor/patch PRs over one PR per package — fewer PRs, and a release has aged before it is proposed.
- [2026-10-30] ci: one Dependabot group for all `@medusajs/*` over per-package PRs — Medusa releases its packages together and they must move in lockstep.
- [2026-10-30] ci: payment SDKs (`@adyen/*`, `@stripe/*`) left out of every Dependabot group — each bump touches checkout and gets its own PR and review.
- [2026-10-30] ci: hold back majors of next, react, typescript, tailwindcss, @types/node and their companions (react-dom, eslint-config-next, @types/react*) over letting Dependabot propose them — the Medusa starter pins them and a major is a hand-done migration.
- [2026-10-31] ci: checks run on push to main as well as on PRs, over PR-only — the repo is public with a `protect-main` ruleset (PR-only, `checks` + `integration` required, branch up to date), so main is guarded, but Deploy staging is triggered by a successful push run of PR checks. Supersedes the 2026-10-30 entry, whose reason (no ruleset on a private free repo) no longer holds.
- [2026-10-30] ci: a separate `tsc --noEmit` step over relying on `next build` — `next.config.js` sets `typescript.ignoreBuildErrors`, so the build never type-checks.
- [2026-10-30] ci: actions pinned to commit SHAs over tags, kept current by Dependabot — a moved tag cannot change what runs.
- [2026-10-31] storefront: security headers set in `next.config.js` over a reverse proxy — no hosting is chosen yet, and the app then carries them wherever it runs.
- [2026-10-31] storefront: CSP staged — `frame-ancestors`, `base-uri` and `object-src` enforced now, the full policy report-only — enforcing an unverified allowlist can silently stop the Adyen or Stripe checkout from loading. Enforce only after Adyen card + 3-D Secure, Click to Pay, Apple Pay, Google Pay and Stripe have each been exercised in a live-like environment with clean reports; narrow `*.adyen.com` to the documented hosts then.
- [2026-10-31] storefront: `script-src 'unsafe-inline'` over nonces for now — Next.js hydration needs inline scripts, and nonces force every page to render dynamically. Before enforcing, add nonces with `strict-dynamic` on `/checkout` at least (it renders dynamically anyway): with `unsafe-inline` the policy gives no XSS protection.
- [2026-10-31] storefront: `frame-src https:` over an exact list — 3-D Secure challenges load the card issuer's page, which can be any origin.
- [2026-10-31] storefront: CSP has no `report-uri` yet — the natural sink is Sentry's CSP endpoint, added with Sentry; until then violations show only in the browser console.
- [2026-10-31] storefront: HSTS without `includeSubDomains` over the full form — no domain is chosen; on an apex domain it would force every subdomain (backend, admin, staging) to HTTPS for a year. Add it, then `preload`, once every subdomain serves HTTPS.
- [2026-10-31] storefront: `NEXT_PUBLIC_MEDUSA_BACKEND_URL` required at build over an empty CSP fallback — once enforced, a missing backend origin would silently block every browser call to the backend.
- [2026-10-31] hosting: staging on the shared Coolify staging server with images built in GitHub Actions and pulled from GHCR, over building on the server or a server upgrade — the server has ~0.8 GB free and Medusa admin + Next.js builds need 1-1.5 GB each; the repo is public, so Actions minutes are free.
- [2026-10-31] hosting: no Redis on staging — Medusa's in-memory event bus, cache and workflow engine are fine for one instance and save memory on a full server. Production should add the Redis modules.
- [2026-10-31] hosting: images tagged with the full commit sha and deployed through a restricted SSH key whose forced command only accepts a sha, over giving the workflow a Coolify API token — a leaked key can only redeploy a commit.
- [2026-10-31] hosting: backend image installs its runtime deps with `npm install` in `.medusa/server` without a lockfile, over shipping the workspace's hoisted node_modules — Medusa's build copies a lockfile only from `apps/backend` and the root lockfile does not match that package.json; `@medusajs/*` are pinned exactly, so only their transitive deps float. devDependencies are stripped from that package.json first: without a lockfile, npm still resolves them under `--omit=dev` and their peer ranges can conflict. Revisit before production (e.g. a backend-only lockfile).
- [2026-10-31] hosting: staging host details (address, access gate, file layout) kept out of this public repo, over documenting them in ops/STAGING.md — they map the shared server for an attacker.
- [2026-10-31] ci: Dependabot ignores react-i18next, react-router-dom and @tanstack/react-query entirely — the backend pins them to @medusajs/dashboard's exact versions so admin extensions share its instance; they move by hand with a Medusa bump. This also suppresses security-update PRs for them, so a vulnerable pin is flagged only by Dependabot alerts (which must be on); the fix is a Medusa bump or a re-sync to the dashboard's versions.
- [2026-10-31] ci: Dependabot holds back vite majors (`@medusajs/admin-bundler` requires ^7) and tailwindcss-radix majors (v4's `group-radix-*` variants need Tailwind 4; under Tailwind 3 the product-tab accordion silently loses them) — CI is green on both, the breakage is only at runtime.
- [2026-10-31] backend: `medusa-config.ts` refuses to start outside development/test (allow-list, so NODE_ENV=staging is checked) on missing or template DATABASE_URL, CORS lists that are not https production origins, or JWT/cookie secrets that are template, short, low-variety or equal — Medusa itself only rejects a missing secret. `medusa build` is exempt because secrets are runtime-only.
- [2026-10-31] ci: backend HTTP integration tests run in their own job against a Postgres service container (from mirror.gcr.io) — the stone-items route, its hook and core migrations are only exercised against a real database.
- [2026-10-31] backend: the stone-items workflow checks the variant's product is published and in the cart's sales channel — it looks the variant up by id, so without the check a draft or other-channel stone product could be added (still priced on the server).
- [2026-10-31] ci: the staging URL, host and known_hosts line are repository secrets, not variables, and image provenance is `mode=min` — the repo and its Actions logs are public, and variables print in clear text and mode=max records build args in the attestation.
- [2026-10-31] hosting: production under the existing Coolify on an existing server, over a new VPS — it has the room; pre-launch access is IP-restricted at the proxy for granit-form's hostnames only. Server and gate details are in the private ops notes, not this public repo.
- [2026-10-31] providers: Adyen for payments, Resend for e-mail, Hetzner Object Storage for product images and off-site backups, Sentry projects per app — one payment provider to test; the rest match what the owner already runs.
- [2026-10-31] storefront: `X-Robots-Tag: noindex` on every build whose `APP_ENV` is not `production`, over a robots.txt Disallow — a crawler must fetch a page to drop it, and keying on "not production" starts a new environment hidden.
- [2026-10-31] hosting: curl in both runtime images for Coolify's health check, over Docker HEALTHCHECK with node — Coolify's check runs curl in the container, and with it off a failed deploy is invisible. The storefront check is liveness only so a backend outage does not roll it back.
- [2026-10-31] hosting: the backend image takes its production node_modules from `npm ci --omit=dev --workspace @dtc/backend` against the root lockfile, over installing without a lockfile in `.medusa/server` or deriving a standalone backend lockfile — the image then runs exactly the versions CI tested, with one lockfile; a rewritten lockfile failed `npm ci`'s consistency check on peers. Supersedes the earlier "no lockfile" entry.
- [2026-10-31] ci: PR checks build both deploy images without pushing, over leaving the Dockerfiles to Deploy staging — a broken image otherwise fails only after the merge.
